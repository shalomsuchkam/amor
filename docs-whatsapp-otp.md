# WhatsApp OTP для amorflowers.kz — настройка

## Сначала главное: у вас сейчас ломается почтовый OTP

Это не про WhatsApp, но обнаружилось по дороге и важнее самой задачи.

В `Procfile` стоит:

```
gunicorn app:app --workers 2 --threads 4
```

Два воркера — это **два отдельных процесса операционной системы** со своей
памятью. А выданные коды в старом `otp.py` хранились в обычном словаре
внутри модуля:

```python
_STATE = {}      # (purpose, phone) -> {...}
```

Запрос «отправить код» попадает в первый процесс и код записывается в его
память. Следующий запрос — «проверить код» — балансировщик может отдать
второму процессу, где этой записи нет. Пользователь вводит правильный код
и получает «Сначала запросите код».

Воспроизвёл это двумя отдельными процессами Python, как у gunicorn:

```
################ СТАРАЯ ВЕРСИЯ ################
  процесс 1 (отправка): ok=True  err=None
  процесс 2 (проверка): ok=False err=Сначала запросите код.

################ НОВАЯ ВЕРСИЯ ################
  процесс 1 (отправка): ok=True  err=None
  процесс 2 (проверка): ok=True  err=None
```

Примерно половина регистраций и сбросов пароля на боевом сайте сейчас
завершается ошибкой на верном коде. Плюс любой перезапуск сервиса обнуляет
все выданные коды разом.

**Это работает прямо сейчас на build 43 с почтой через Brevo** — чинится тем
же новым `otp.py`, независимо от того, будете ли вы подключать WhatsApp.

Тест лежит в `otp_worker_test.py`, запускается одной командой:
`python3 otp_worker_test.py old` и `python3 otp_worker_test.py new`.

## Деньги: считаем до 1 октября

С 1 октября 2026 Казахстан выделяют в отдельную строку прайса Meta.
Ставка за коды подтверждения растёт **с $0,0077 до $0,018** — примерно
с 3 до 8 тенге за сообщение.

| Регистраций в месяц | Стоимость |
|---------------------|-----------|
| 100 | ~800 ₸ |
| 500 | ~4 000 ₸ |
| 1 000 | ~8 000 ₸ |

Для вашего оборота это незначимо. Но появляется риск, которого у бесплатной
почты не было: **бот дёргает форму регистрации и жжёт ваши деньги.** Лимит
на один номер от этого не спасает — номера перебираются.

Поэтому в новом `otp.py` есть общий потолок отправок по всему сайту:

```python
MAX_TOTAL_PER_DAY = 300     # OTP_MAX_TOTAL_PER_DAY
```

При 300 отправках максимальный ущерб за сутки — около 2 400 ₸. Поднимете,
когда увидите реальный поток регистраций.

Отдельно: у Meta есть тариф **authentication-international** — он применяется,
когда код уходит в страну, отличную от страны регистрации вашего номера, и он
в разы дороже. У вас бывают заказы из-за рубежа, поэтому ограничение по коду
страны я **не включал**, но оставил переключателем:

```
OTP_ALLOWED_PREFIXES=7     # только +7; пусто = любые страны
```

## Номер: берите отдельный

Не вешайте WABA на **+7 707 660 66 00**.

На этот номер идёт вся реклама (~$10 000/мес), он в шапке инстаграма с 49k
подписчиков и на сайте. При подключении к WhatsApp Business Platform номер
переходит в другой режим: обычное приложение WhatsApp на нём больше не
работает, а менеджеры сейчас отвечают клиентам именно через него в Wazzup.

Отдельный номер под OTP стоит копейки и полностью развязывает риски:
отклонённый шаблон, превышение лимита или блокировка не заденут продажи.

## Настройка в Meta (30–40 минут)

У вас уже есть бизнес-аккаунт Meta с рекламным кабинетом и страницей
«Amor GRAND» — WABA создаётся внутри него.

### 1. Создать WhatsApp Business Account

business.facebook.com → **Настройки** → **Аккаунты** → **WhatsApp-аккаунты** →
Добавить. Привязать к существующему бизнес-портфелю.

### 2. Добавить номер

В созданном WABA → **Номера телефонов** → Добавить.
Номер должен быть новым для WhatsApp: если на нём уже есть обычный WhatsApp,
его придётся сначала удалить.

После подтверждения по SMS/звонку скопируйте **Phone number ID** — это не сам
номер, а длинное число рядом с ним.

### 3. Создать шаблон Authentication

**Инструменты аккаунта** → **Шаблоны сообщений** → Создать.

- Категория: **Authentication** (не Marketing и не Utility — у Authentication
  свой тариф и быстрая модерация)
- Название: `amor_otp`
- Язык: **русский**
- Тип кнопки: **Copy code**
- Срок действия кода: 5 минут

Текст у Authentication-шаблонов фиксированный, Meta подставляет его сама —
писать свой нельзя. Это нормально и упрощает модерацию: такие шаблоны
обычно одобряют за минуты.

Если захотите казахский и английский — создайте шаблоны с тем же именем
`amor_otp`, но другим языком, и меняйте `WHATSAPP_TEMPLATE_LANG`.

### 4. Получить постоянный токен

**Не берите временный токен из Getting Started** — он живёт 24 часа, и через
сутки регистрация на сайте встанет.

Нужен токен системного пользователя:

business.facebook.com → **Настройки** → **Пользователи** → **Системные
пользователи** → Добавить (роль: Администратор) → **Создать токен**:

- Приложение: ваше WhatsApp-приложение
- Срок действия: **Бессрочный**
- Права: `whatsapp_business_messaging`, `whatsapp_business_management`

Токен показывается один раз — сохраните сразу.

### 5. Прописать переменные на сервере

```bash
OTP_CHANNELS=whatsapp
WHATSAPP_TOKEN=<токен системного пользователя>
WHATSAPP_PHONE_ID=<Phone number ID из шага 2>
WHATSAPP_TEMPLATE=amor_otp
WHATSAPP_TEMPLATE_LANG=ru
OTP_MAX_TOTAL_PER_DAY=300
```

Перезапустить сервис. Всё.

## Запасной канал

`OTP_CHANNELS` теперь принимает список через запятую, в порядке приоритета:

```
OTP_CHANNELS=whatsapp,telegram
```

Если у номера нет WhatsApp, код уйдёт через Telegram Gateway на тот же номер.
Нужен `TELEGRAM_GATEWAY_TOKEN` с gateway.telegram.org (это не токен бота).

Важная деталь в логике: на запасной канал переключение происходит **только**
когда адресат недоступен именно в этом мессенджере. Если у вас не одобрен
шаблон или протух токен — ошибка показывается сразу, а не прячется за тихим
переключением. Иначе поломка настройки осталась бы незамеченной, а вы бы
платили за оба канала.

Почту в цепочку с телефоном поставить нельзя — на номер телефона письмо не
отправишь. Почта остаётся отдельным режимом: `OTP_CHANNELS=email`.

Старая переменная `OTP_CHANNEL` (один канал) продолжает работать.

## Что изменилось в коде

Один файл — `otp.py`. Публичные функции те же (`send_code`, `check_code`,
`is_verified`, `consume`, `enabled`, `channel_name`, `is_email_channel`),
поэтому `app.py` и шаблоны трогать не нужно.

| Было | Стало |
|------|-------|
| Коды в памяти процесса | Таблицы `otp_codes` / `otp_sends` в SQLite |
| Один канал | Цепочка каналов с запасным |
| Лимит только на адресата | + общий потолок в сутки |
| Номер не проверялся | Проверка длины + фильтр по стране (опционально) |

Таблицы создаются автоматически при первом обращении — `db.py` править
не нужно, миграции запускать тоже.

## Проверка после установки

```bash
python3 otp_worker_test.py new    # состояние переживает смену процесса
python3 otp_test.py               # 22 проверки логики
```

Затем вживую: зарегистрируйтесь на сайте со своего номера, дождитесь кода в
WhatsApp, введите. Если код не пришёл — смотрите статус шаблона в Meta
(должен быть **Active**, не Pending и не Rejected).

## Важная оговорка про версию

Я правил архив **amor-flowers-36**, а в продакшене у вас **build 43** с
почтой через Brevo. Новый `otp.py` самодостаточен и опирается только на
`db.DB_PATH`, так что должен встать в 43 как есть — но проверьте, что в
вашем `app.py` вызовы OTP не изменились с 36-й версии. Если в 43-м
`otp.py` появилось что-то своё, пришлите его, сведу вручную.
